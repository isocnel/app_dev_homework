Этот API для того, чтобы пользователь вел трекер своих привычек в одном месте и они не терялись между устройствами.

Эндпоинты:
- GET: путь /habits, содержащий список привычек, где можно отфильтровать по статусу и полистать. Вернет 400, 401.
- POST: путь /habits, где можно создать привычку. Вернет 201, 400, 401, 409.
- GET: путь /habits/{habitID}, тчобы получить одну привычку. Вернет 200, 401, 403, 404
- PUT: путь /habits/{habitID}, чтобы обновить привычку целиком. Вернет 200, 400, 401, 403, 404
- DELETE: путь /habits/{habitID}, чтобы удалить привычку. Вернет 401, 403, 404

Как выполняла:выбрала тему с одним главным ресурсом habits, на котором удобно показать все глаголы. Сначала накидала, какие операции нужны. Привычки решила не удалять, а отправлять в архив.
Спеку собирала в editor.swagger.io. Сначала написала paths, добавила components. Запустила генератор: npx @openapitools/openapi-generator-cli generate -i api.yaml -g spring -o service \
  --additional-properties=interfaceOnly=true,useSpringBoot3=true,useTags=true.

  interfaceOnly=true, потому что мне нужны только интерфейсы и модели. После генерации проверила, что в HabitsApi пять методов, а в model все схемы из спеки. И на всякий случай прогнала mvn compile.
  Руками добавила 409 на повтор названия, т.к. без него неопнятно, что делать, если человек дважды завел одну и ту же привычку.

В схемах есть Habit, HabitCreate, HabitUpdate, HabitPage, Frequency, HabitStatus и Error. Клиент присылает HabitCreate при создании и HabitUpdate при обновлении, а получает Habit. OwnerId, внутренние флаги и служебные поля остаются на стороне сервера и не отдаются наржуу.
